Current Tree-Aware Heuristic: Steps, Parameters, and Cost
==========================================================

Code path
---------

Main implementation:
    min-error-sequential/src/heuristic.py

Used by:
    min-error-sequential/01_compact_exact_comparison.ipynb
    min-error-sequential/03_scalable_algorithm_comparison.ipynb
    min-error-sequential/04_heuristic_diagnostics.ipynb

The heuristic optimizes the same surrogate objective used by the sequential
minimum-error formulation. It does not use the actual Helstrom third-field
branch probabilities during optimization. Actual error is only used later as a
separate reevaluation.


Inputs for one problem case
---------------------------

For each generated input case, the runner loads one sparse CSV file using
load_sparse_input(...). This returns:

    K:
        Number of possible fields.

    M:
        Number of sensor locations.

    phase_gaps:
        Stored phase differences r_ijm for every field pair (i,j) and location m.
        The heuristic itself does not use phase_gaps directly.

    pijmn:
        Pairwise Helstrom error table. For each pair (i,j), location m, and
        sensor count n, this gives P_ijmn, the two-field minimum error if n
        sensors at location m are used to distinguish i from j.

The heuristic also receives the total budget N. It returns:

    allocation:
        A length-M vector. allocation[m] is the number of sensors assigned to
        location m.

    pair_locations:
        For every pair (i,j), the location selected as best under the final
        allocation.

    decision_tree:
        A sequential elimination tree.

    error_probability:
        The final surrogate tree error.


Parameters currently used in the main notebooks
-----------------------------------------------

The compact exact comparison notebook and scalable comparison notebook use:

    beam_width = 3
    max_iterations = 3
    improvement_threshold = 1e-5
    initialization = "greedy"
    move_shortlist_size = 1
    random_seed = 0              # default, not active for greedy initialization
    include_greedy_start = True  # default

Interpretation:

    beam_width:
        Number of partial decision trees retained during tree construction.
        Larger values examine more tree structures but increase cost.

    max_iterations:
        Maximum number of accepted allocation-refinement rounds.

    improvement_threshold:
        A candidate allocation is accepted only if the rebuilt full-tree
        surrogate error improves by at least this amount.

    initialization = "greedy":
        Start from the allocation returned by the Greedy algorithm.

    move_shortlist_size = 1:
        Rank all one-sensor transfers using a cheap proxy objective, but rebuild
        the full decision tree only for the single best-ranked transfer.

The beam-width diagnostics notebook tests beam_width values (1, 3, 5), with the
same max_iterations, improvement_threshold, and greedy initialization.


Algorithm steps
---------------

1. Validate the case.

   The heuristic checks K, M, N, and the pairwise error table pijmn. It requires
   every pair (i,j), every location m, and finite error probabilities in [0, 0.5].

2. Build one or more starting allocations.

   With the current notebook setting initialization = "greedy", the only
   starting allocation is the Greedy allocation. If initialization were
   "near_uniform" or "random", the code can also include a Greedy start, but that
   is not the current main setting.

3. Score each starting allocation by rebuilding a decision tree.

   For a fixed allocation, the code first finds the best available location for
   each field pair:

       pair_locations[(i,j)] = argmin_m P_ijm,allocation[m]
       pair_errors[(i,j)]   = min_m    P_ijm,allocation[m]

   If a location has no stored error value for the available sensor count, that
   location contributes error 0.5 for that pair.

4. Build a tree for that allocation using beam search.

   The root starts with all K fields still possible. At each unfinished tree
   position, the algorithm tries every pair among the fields still remaining.
   Testing pair (i,j) creates two children:

       discard_i: the branch where field i is eliminated
       discard_j: the branch where field j is eliminated

   Partial trees are scored using the same surrogate branch model:

       if true field is i:
           branch discarding i has probability pair_error
           branch discarding j has probability 1 - pair_error

       if true field is j:
           branch discarding j has probability pair_error
           branch discarding i has probability 1 - pair_error

       if true field is neither i nor j:
           each branch has probability 0.5

   After each expansion, only the best beam_width partial trees are retained.
   When all retained trees are complete, the complete tree with the lowest
   surrogate error is selected.

5. Keep the best starting allocation/tree.

   If there are multiple starting allocations, the algorithm chooses the one with
   the lowest rebuilt surrogate tree error. Ties are broken deterministically by
   allocation order.

6. Compute pair weights from the current tree.

   The current tree is traversed from the root with initial field masses 1/K.
   Each time the tree tests pair (i,j), the pair receives weight:

       current mass of field i + current mass of field j

   Mass is propagated using the surrogate rule above. If the same pair appears
   multiple times in the tree, its weights are added. These weights estimate
   which pairwise tests matter most to the current sequential tree.

7. Rank all one-sensor transfer moves using a cheap proxy objective.

   A candidate move transfers one sensor from a nonempty source location to a
   different destination location. For each candidate allocation, the code
   recomputes the best pair location and pair error for every pair, then scores:

       J(candidate) = sum_over_pairs weight(pair) * candidate_pair_error(pair)

   Only candidates with J(candidate) below the current J are kept. They are
   sorted by J and then by allocation for deterministic tie-breaking.

8. Rebuild the full tree only for the shortlisted moves.

   The current notebook uses move_shortlist_size = 1, so only the single
   best-ranked proxy move gets a full beam-search tree rebuild. This is the main
   cost-control change: all moves are considered by the proxy, but only a small
   number are evaluated with the expensive tree objective.

9. Accept the best fully evaluated move only if it improves the real surrogate
   tree objective.

   A move is accepted only when:

       candidate_tree_error < current_tree_error - improvement_threshold

   With the current setting, improvement_threshold = 1e-5.

10. Stop.

   The loop stops when either:

       max_iterations accepted/refinement attempts have been reached, or
       no shortlisted move improves the full rebuilt tree enough.


Cost summary
------------

Let:

    P = K(K-1)/2       number of field pairs
    B = beam_width
    I = max_iterations
    L = move_shortlist_size
    S = number of stored sensor-count entries per pair/location

For one fixed allocation:

    Computing best pair errors costs roughly O(P M S).

    Building a tree with beam search costs roughly O(B K P K^2) in a conservative
    implementation-level count: about K-1 expansion rounds, up to B retained
    partial trees, up to P candidate pair tests per expansion, and mass-based
    scoring over selected tree nodes and K fields.

For one local-search iteration:

    Ranking one-sensor transfers examines at most M(M-1) moves. Each move
    recomputes pair errors, so the proxy-ranking cost is roughly:

        O(M^2 P M S)

    Full tree rebuilding costs:

        O(L * tree_build_cost)

With the notebook setting L = 1 and I = 3, the expensive part is bounded tightly:
after the initial tree build, at most one full tree rebuild is attempted per
iteration. That is why the current heuristic is much cheaper than a broad search
over many rebuilt trees.


Important reporting wording
---------------------------

This method should be described as:

    A tree-aware local allocation heuristic initialized from Greedy. For each
    allocation it constructs a sequential decision tree by beam search under the
    surrogate 0.5/0.5 outside-pair branch model. Allocation refinement uses
    tree-derived pair weights to rank one-sensor transfer moves, then fully
    reevaluates only a small shortlist of moves using the rebuilt surrogate tree.

Do not describe it as actual-error optimization. The actual error is only used
afterward to reevaluate the fixed final allocation and decision tree.
