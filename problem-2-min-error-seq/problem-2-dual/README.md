# Problem 2 dual: sensor budgets for a target error

Greedy and VND + Beam Search budget searches for paper §4.5. Reported counts are verified feasible solutions, not certified global minima. The VND, beam search and binary budget-search procedures are unchanged.

Open `01_extended_analysis.ipynb` using the root README environment and existing Problem 2 extended inputs. No separate dataset generation is needed.

- `RUN_MODE='full'` or `'compact'` (the previous `test` selection; `test` remains an alias).
- `METHODS=('vnd_beam', 'greedy')` selects both; select either alone to run only that method.
- `RUN_ANALYSIS=True` runs missing work; `RESUME=True` retains completed searches.
- `RUN_ANALYSIS=False` reads `SAVED_RESULTS` and rebuilds reports without searches or error evaluations. It uses the saved metadata, regardless of the current `METHODS` setting.
- `MAX_SENSOR_BOUND=5000` retains all 4,320 instances in the current full dataset, 2,160 per dimension; zero exclusions. `None` disables the cutoff. Coverage is recomputed for the selected dataset.

Each target (default 0.1–0.5) starts with budget bounds 0 and the sequential perfect-discrimination minimum. Actual tree error determines each binary-search update. Heuristic feasibility need not be monotone, so returned budgets are the smallest verified feasible budgets visited, not optimality certificates.

## Storage and reuse

Reports overwrite `results/full/` or `results/compact/` directly. `solutions.json`, `failures.json` and `run_info.json` describe the latest selected run. Per-method exports also remain in `methods/<algorithm>/`; unselected methods are preserved. The figure uses matched completed cases when both methods are present and shows median feasible counts and interquartile bands.

All original per-instance/target checkpoints remain in `results/cache/`. Cache identities depend on the selected solver, evaluator, budget-search logic and settings, not notebook/report changes or the other algorithm. `compatible_signatures.json` maps audited storage-only updates to their original cache keys. Preserve this file with the caches. Cutoff and target-list changes reuse completed compatible targets.

The latest full exports use the flat directory. The compact solution view was rebuilt from the current full-run subset without solving again; its plots/tables can be regenerated by the notebook. Older exports and obsolete checkpoint versions were removed; `comparison_limited`, `comparison`, `greedy` and hashed report directories are no longer active output paths. Historical public runner entry points delegate to the same storage policy.

`dual_search.py` contains the unchanged budget-search implementation; `budget_limited.py` handles method selection, cutoff and cache reuse; `reporting.py` builds the paired summaries and plots. No research study was rerun during this storage migration.
